# GPU on the Fediverse (ActivityPub)

The GPU network is reachable from Mastodon, Pleroma, Misskey and any other
[ActivityPub](https://www.w3.org/TR/activitypub/) server — for example
[defcon.social](https://defcon.social).

**Follow `@gpu@gpu.social` and mention it with a question — it answers in the thread.**

```
@alice@defcon.social:  @gpu@gpu.social what is a transformer?
@gpu@gpu.social:       @alice@defcon.social A transformer is a neural network that ...
@alice@defcon.social:  @gpu@gpu.social and attention?          ← follow-up keeps context
```

Implemented in [`gpu_activitypub.py`](./gpu_activitypub.py) on top of
[pubby](https://git.jon-e.net/jonny/pubby), which handles WebFinger, NodeInfo,
the actor document, inbox/outbox, delivery and HTTP signatures.

## Behaviour

| Incoming | Bot does |
|----------|----------|
| Public post mentioning `@gpu` | Public reply in the thread |
| Unlisted post | Unlisted reply |
| Followers-only post / direct message | Direct reply (never published, never served) |
| Reply to one of the bot's answers | Answers with the earlier Q/A of the thread as context |
| Post with a content warning | Reply keeps the same content warning |
| Like, boost, quote, reply in an unrelated thread | Ignored |
| Post from another bot (`Service`/`Application` actor) | Ignored — no bot-to-bot loops |
| Same activity delivered twice | Answered once |
| More than 5 mentions from one account in 10 min | Ignored until the window passes |

Answers are generated by the GPU OpenAI-compatible API
(`/v1/chat/completions`) and truncated to 4000 characters (the defcon.social
limit). Generation happens in a background thread, so remote servers get
`202 Accepted` immediately.

## Federating with defcon.social

`python experiments/activitypub/check_instance.py defcon.social` reports:

```
software:        mastodon 4.7.3
max characters:  4000
webfinger:       @defcon@defcon.social -> https://defcon.social/users/defcon
unsigned GET:    HTTP 401 -> authorized fetch ON (signed requests required)
```

defcon.social runs with **authorized fetch**, so unsigned requests for actor
documents are rejected. pubby signs every outgoing GET and POST with the bot's
key, and the bot's own actor document is public, so defcon.social can verify
our signatures. Run the probe against any other instance before announcing
the bot there.

## Run

```bash
pip install -r requirements-activitypub.txt
export GPU_API_KEY=...                    # key from the GPU app / gpu_client.py
python gpu_activitypub.py                 # dev server on 127.0.0.1:8000
```

Production (one process: the redelivery cache and rate limits are in memory):

```bash
gunicorn -w 1 --threads 8 -b 127.0.0.1:8000 'gpu_activitypub:create_app()'
```

The server must be served over HTTPS at the domain in `GPU_AP_BASE_URL`.
Behind nginx, forward these paths and **keep the original `Host` header**:
it is part of the HTTP signature remote servers send.

```nginx
location ~ ^/(\.well-known/(webfinger|nodeinfo)|nodeinfo/|ap/) {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
}
```

### Configuration

| Variable | Default | Meaning |
|----------|---------|---------|
| `GPU_AP_BASE_URL` | `https://gpu.social` | Public URL of the server; handle domain |
| `GPU_AP_USERNAME` | `gpu` | Handle → `@gpu@gpu.social` |
| `GPU_AP_DATA_DIR` | `~/.gpu/activitypub` | Key (`actor.pem`), followers, replies |
| `GPU_API_BASE` | `https://gpu.social` | OpenAI-compatible API used for answers |
| `GPU_API_KEY` | — | API key |
| `GPU_AP_MODEL` | `qwen2.5-14b` | Model for answers |
| `GPU_AP_MAX_CHARS` | `4000` | Maximum reply length |
| `GPU_AP_ALLOWED_INSTANCES` | — | Comma-separated allow-list, e.g. `defcon.social` |
| `GPU_AP_BLOCKED_INSTANCES` | — | Comma-separated block-list |
| `GPU_AP_HOST` / `GPU_AP_PORT` | `127.0.0.1` / `8000` | Dev server bind address |
| `GPU_AP_LOG_LEVEL` | `INFO` | Set `DEBUG` to trace federation traffic |

**Back up `actor.pem`.** It is the bot's identity: if it changes, remote
servers can no longer verify the bot's signatures.

## Endpoints

| Method | Path | |
|--------|------|-|
| `GET` | `/.well-known/webfinger` | `acct:gpu@gpu.social` → actor |
| `GET` | `/.well-known/nodeinfo`, `/nodeinfo/2.1` | Server metadata |
| `GET` | `/ap/actor` | Bot profile (`Service`, shown as a bot) |
| `POST` | `/ap/inbox` | Signed activities from other servers |
| `GET` | `/ap/outbox`, `/ap/followers`, `/ap/following` | Collections |
| `GET` | `/ap/notes/<id>` | Public answers |

## Tests

```bash
pip install -r requirements-activitypub.txt pytest
python -m pytest tests -v
```

The tests simulate a defcon.social user end to end: activities are signed
with a real RSA key the way Mastodon signs them, delivered to the inbox, and
the bot's reply is captured on its way to `https://defcon.social/inbox`.
No network access is needed.
